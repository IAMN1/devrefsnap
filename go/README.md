## Базовый уровень

### Команды модуля

Создай отдельную учебную папку и сохрани туда [все файлы модуля](language.md#полный-модуль), затем добавь файлы со страниц конкурентности и HTTP. Установленный Go должен поддерживать версию из `go.mod`; команды ниже не требуют сторонних библиотек.

```bash
go version
gofmt -w .
go run ./cmd/demo
go test ./...
go vet ./...
go test -race ./...
```

`gofmt -w` перезаписывает форматирование `.go`-файлов в этой учебной папке. `go run` компилирует и запускает программу; `go test` запускает тесты, `vet` проверяет подозрительные конструкции, race detector ищет гонки только на выполненных путях. Он требует поддерживаемой платформы/средств сборки и не доказывает отсутствие всех гонок.

Для нового проекта без готового `go.mod` выполни `go mod init example.com/cheatsheet`. `go mod tidy` синхронизирует зависимости с импортами и может менять `go.mod`/`go.sum`, а при внешних модулях — обращаться в сеть. В этом примере внешних модулей нет. Toolchain для проверок закреплён через `GOTOOLCHAIN=local`; при несовпадении версий обновляй окружение явно.

### Что знать до первого рецепта

| Конструкция | Смысл |
| --- | --- |
| `package`, `import` | Один пакет на каталог; импортируются используемые зависимости |
| `var n int`, `name := "Alice"` | Объявление; `:=` используется внутри функции |
| `func f(x int) (int, error)` | Типы аргументов и несколько результатов |
| `if`, `switch`, `for`, `range` | Условия, выбор, цикл; отдельного `while` нет |
| `defer f()` | Выполнить при выходе из функции; аргументы вычисляются при defer |
| Имя с заглавной буквы | Экспортируется из пакета |

## Средний уровень

Сначала определяй структуру данных и ошибки функции, затем интерфейс на стороне потребителя. Реализация интерфейса не требует отдельного `implements`. Pointer receiver нужен для изменения объекта; не копируй значения, содержащие уже используемый mutex.

Срез — представление участка массива: два среза могут делить память. `append` может выделить новый массив, поэтому сохраняй его результат. Map нужно создать до записи; порядок обхода не задан. Строка — неизменяемая последовательность произвольных байтов, не обязательно корректный UTF-8. `len(s)` считает байты; `range` декодирует UTF-8 и даёт позиции байтов и rune, а для некорректной последовательности — `utf8.RuneError`.

[Языковой рецепт](language.md) проверяет ошибки через `errors.Is`/`As`, копирование среза и generic-функции. [HTTP-рецепт](http-json.md) показывает отдельные проверки синтаксиса JSON и смысла данных.

## Продвинутый уровень

- [Worker pool](concurrency-and-testing.md) ограничивает количество goroutines и ждёт их завершения. Отмена context кооперативная: код должен читать `Done()`/`Err()`.
- Канал переносит данные/сигналы, mutex защищает инвариант общей памяти. Выбирай по владению данными, а не по лозунгу «всегда каналы».
- Передавай context первым аргументом, вызывай cancel у созданного дочернего контекста и не используй context как контейнер произвольных параметров.
- В HTTP контролируй размер тела, deadline и закрытие ресурсов. `httptest` проверяет handler; он не заменяет нагрузочный тест, TLS и проверку конфигурации сервера.

## Частые ошибки

| Ошибка | Исправление |
| --- | --- |
| Ошибку сравнивают по строке | `errors.Is` для причины, `errors.As` для типа |
| `interface != nil`, хотя внутри nil pointer | Интерфейс nil только без динамического типа и значения |
| Несколько goroutines пишут в map | Защити map mutex или выдели одного владельца |
| Прочитали из закрытого канала как из открытого | Проверяй `value, ok`; закрытие не является значением задания |
| Закрывает канал получатель | Закрывает сторона, знающая, что отправителей больше нет |
| `time.Sleep` вместо синхронизации | Используй канал/WaitGroup/context и ограничение времени в тесте |
| Потеряли результат append | Присвой возвращённый срез |
