## Базовый уровень

### Команды модуля

Создайте отдельный учебный каталог.
Сохраните в каталог [все файлы модуля](language.md#полный-модуль).
Затем добавьте файлы со страниц конкурентности и HTTP.
Установленный Go должен поддерживать версию из `go.mod`.
Команды ниже не требуют сторонних библиотек.

```bash
go version
gofmt -w .
go run ./cmd/demo
go test ./...
go vet ./...
go test -race ./...
```

`gofmt -w` перезаписывает форматирование `.go`-файлов в учебном каталоге.
`go run` компилирует и запускает программу.
`go test` запускает тесты.
`vet` проверяет подозрительные конструкции.
Race detector ищет гонки только на выполненных путях.
Race detector требует поддерживаемой платформы и средств сборки.
Успешная проверка не доказывает отсутствие всех гонок.

Если в новом проекте ещё нет `go.mod`, выполните `go mod init example.com/cheatsheet`.
`go mod tidy` синхронизирует зависимости с импортами.
Команда может менять `go.mod`/`go.sum`.
При наличии внешних модулей команда может обращаться в сеть.
В этом примере внешних модулей нет.
Toolchain для проверок закреплён через `GOTOOLCHAIN=local`.
Если версии не совпадают, обновите окружение явно.

### Что знать до первого рецепта

| Конструкция | Смысл |
| --- | --- |
| `package`, `import` | Один пакет на каталог; импортируются используемые зависимости |
| `var n int`, `name := "Alice"` | Объявление; `:=` используется внутри функции |
| `func f(x int) (int, error)` | Типы аргументов и несколько результатов |
| `if`, `switch`, `for`, `range` | Условия, выбор, цикл; отдельного `while` нет |
| `defer f()` | Выполнить при выходе из функции; аргументы вычисляются при defer |
| Имя с заглавной буквы | Экспортируется из пакета |

## Средний уровень

Сначала определите структуру данных и ошибки функции.
Затем определите интерфейс на стороне потребителя.
Реализация интерфейса не требует отдельного `implements`.
Pointer receiver нужен для изменения объекта.
Не копируйте значения, которые содержат уже используемый mutex.

Срез представляет участок массива.
Два среза могут использовать общую память.
`append` может выделить новый массив.
Сохраняйте результат `append`.
Создайте map до записи в map.
Порядок обхода map не задан.
Строка — неизменяемая последовательность произвольных байтов.
Строка не обязательно содержит корректный UTF-8.
`len(s)` считает байты.
`range` декодирует UTF-8 и возвращает позиции байтов и rune.
Для некорректной последовательности `range` возвращает `utf8.RuneError`.

[Языковой рецепт](language.md) проверяет ошибки через `errors.Is`/`As`, копирование среза и generic-функции. [HTTP-рецепт](http-json.md) показывает отдельные проверки синтаксиса JSON и смысла данных.

## Продвинутый уровень

- [Worker pool](concurrency-and-testing.md) ограничивает количество goroutines и ждёт их завершения. Отмена context кооперативная: код должен читать `Done()`/`Err()`.
- Канал переносит данные или сигналы. Mutex защищает инвариант общей памяти. Выбирайте средство по владению данными. Лозунг «всегда каналы» не задаёт критерий выбора.
- Передавайте context первым аргументом.
- Вызывайте cancel у созданного дочернего контекста.
- Не используйте context как контейнер произвольных параметров.
- В HTTP контролируйте размер тела.
- Задайте deadline.
- Обеспечьте закрытие ресурсов.
- `httptest` проверяет handler. Эта проверка не заменяет нагрузочный тест, проверку TLS и конфигурации сервера.

## Частые ошибки

| Ошибка | Исправление |
| --- | --- |
| Ошибку сравнивают по строке | `errors.Is` для причины, `errors.As` для типа |
| `interface != nil`, хотя внутри nil pointer | Интерфейс nil только без динамического типа и значения |
| Несколько goroutines пишут в map | Защитите map через mutex или выделите одного владельца |
| Прочитали из закрытого канала как из открытого | Проверяйте `value, ok`. Закрытие не является значением задания |
| Закрывает канал получатель | Закрывает сторона, знающая, что отправителей больше нет |
| `time.Sleep` вместо синхронизации | Используйте канал, WaitGroup или context. Ограничьте время теста |
| Потеряли результат append | Присвойте возвращённый срез |
