## Основные операции

**Ситуация:** нужно создать заметку и подготовить копию, сохранив исходный файл.
Выберите операцию по нужному изменению; таблица содержит отдельные справочные фрагменты.
Сначала проверьте `pwd`.
Затем замените пути своими:

| Задача | Фрагмент | Последствие |
| --- | --- | --- |
| Создать каталог | `mkdir -p project/data` | Создаёт недостающие каталоги |
| Записать текст | `printf '%s\n' 'hello' > note.txt` | `>` создаёт или перезаписывает файл |
| Дописать | `printf '%s\n' 'next' >> note.txt` | Дописывает в конец |
| Скопировать | `cp -i source.txt copy.txt` | `-i` спрашивает перед перезаписью; ответ читается из stdin |
| Переместить | `mv -i copy.txt archive.txt` | Меняет имя/расположение, может перезаписать адресат |
| Удалить файл | `rm -i -- archive.txt` | Удаляет имя файла; shell-корзины обычно нет |
| Удалить пустой каталог | `rmdir empty-dir` | Отказывает для непустого каталога |
| Посмотреть содержимое | `less note.txt`, `head -n 10 note.txt`, `tail -n 20 note.txt` | Чтение; `tail -f` продолжает ожидать новые строки |

Учитывайте glob: shell раскрывает `rm *.log` до запуска rm.
Если путь начинается с дефиса, используйте `./-name` или поддерживаемый командой `--` перед операндами.
`ln -s TARGET LINK` создаёт символическую ссылку.
Относительный TARGET вычисляется от каталога LINK.
Перед удалением или архивированием проверьте, как команда обрабатывает символические ссылки.

## Безопасный практический пример

Полный скрипт использует синтетические логи и путь с пробелом.
Скрипт выполняет поиск, создаёт архив и сравнивает восстановленный файл.
Запустите `bash example.sh`.
Удаление ограничено каталогом, созданным `mktemp -d`.

<!-- example: linux/example.sh -->
```bash
#!/usr/bin/env bash
set -euo pipefail
task_dir=$(mktemp -d "${TMPDIR:-/tmp}/linux-files.XXXXXX")
trap 'rm -rf -- "$task_dir"' EXIT
mkdir "$task_dir/source" "$task_dir/restored"
printf 'INFO started\nERROR missing\nINFO done\n' > "$task_dir/source/app log.txt"
cp "$task_dir/source/app log.txt" "$task_dir/source/copy.txt"
cmp "$task_dir/source/app log.txt" "$task_dir/source/copy.txt"
mv "$task_dir/source/copy.txt" "$task_dir/source/renamed.txt"
test "$(grep -c '^INFO' "$task_dir/source/app log.txt")" -eq 2
test "$(awk '$1 == "ERROR" {print $2}' "$task_dir/source/app log.txt")" = missing
find "$task_dir/source" -type f -name '*.txt' -exec wc -l {} +
tar -cf "$task_dir/logs.tar" -C "$task_dir" source
tar -xf "$task_dir/logs.tar" -C "$task_dir/restored"
cmp "$task_dir/source/app log.txt" "$task_dir/restored/source/app log.txt"
gzip -c "$task_dir/source/app log.txt" > "$task_dir/log.txt.gz"
gzip -cd "$task_dir/log.txt.gz" | cmp "$task_dir/source/app log.txt" -
chmod u=rw,go= "$task_dir/source/app log.txt"
printf 'files OK\n'
```

Ожидается `files OK`.
Строки `wc` зависят от случайного временного пути.
Не распаковывайте недоверенный архив в важный каталог.
Сначала просмотрите `tar -tf archive.tar`.
Оцените пути и ссылки в архиве.
Выберите изолированный каталог для распаковки.

## Текст, потоки и коды выхода

**Ситуация:** в существующем `app.log` есть строка `ERROR missing`; нужно сохранить ошибки отдельно от диагностики команды.
Выберите строки через `grep`; перенаправьте stdout и stderr в разные файлы.

Фрагменты читают указанный файл и формируют вывод.
`2>` перезапишет лог ошибок.

```bash
grep -n -E 'ERROR|WARN' app.log
sed -n '1,20p' app.log
awk '{print $1}' app.log | sort | uniq -c
grep 'ERROR' app.log > output.txt 2> error.txt
```

Фрагменты предполагают существующий `app.log`.
**Результат:** последняя строка помещает `ERROR missing` в `output.txt`; `error.txt` содержит только диагностику самой команды.
При каждом запуске оба файла перезаписываются.
`2>&1` направляет stderr в текущее назначение stdout.
Порядок `>file 2>&1` имеет значение.
Пайп `cmd | tee output.txt` обычно сообщает статус последней команды.
В Bash `set -o pipefail` учитывает неуспех любой команды пайпа.
`set -e` имеет исключения и не заменяет явную обработку ожидаемых статусов.

GNU grep возвращает 0 при совпадении, 1 при отсутствии совпадения и 2 при ошибке.
Другие реализации могут иметь дополнительные коды ошибки.
Если отсутствие строки ожидается, используйте `if grep ...; then ...; else ...; fi`.
Различайте код 1 и ошибку.
`grep -q` может завершиться рано.
При раннем завершении `grep -q` производитель в большом пайпе может получить SIGPIPE.

## Поиск файлов с необычными именами

**Ситуация:** нужно посчитать строки в `.log`-файлах, включая `app log.txt`.
Передайте найденные пути отдельными аргументами, не разбирая текст списка имён.

**Пример — фрагмент для текущего дерева файлов:**

```bash
find . -type f -name '*.log' -exec wc -l {} +
```

**Результат:** `wc` получает целое имя каждого файла, включая пробелы.
Порядок строк зависит от обхода дерева.

`find . -type f -name '*.log' -print` выбирает имена.
Кавычки не дают shell раскрыть wildcard заранее.
Не разбирайте вывод `ls`.
Не передавайте список с разделителем newline в `for file in $(...)`.
Для передачи имён аргументами предпочитайте `find ... -exec command {} +`.
Совместимая пара `-print0` / `xargs -0` также сохраняет пробелы и переводы строк в именах.
Сначала выведите выбранные пути.
Затем отдельно примите решение об изменении или удалении.

| Задача | GNU/Linux | BSD/macOS |
| --- | --- | --- |
| Метаданные файла | `stat -c '%a %n' file` | `stat -f '%Lp %N' file` |
| Дата относительно текущей | GNU `date -d 'yesterday'` | BSD `date -v-1d` |
| In-place sed | `sed -i 's/old/new/g' file` | `sed -i '' 's/old/new/g' file` |
| Форматированный find | GNU `find ... -printf ...` | Обычно нет `-printf` |

Таблица показывает различия реализаций.
Команды из таблицы не переносимы между ОС без проверки.
Для переносимого преобразования проще сначала записать новый файл.
Проверьте новый файл.
Только затем замените исходный файл.
