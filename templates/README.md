# Шаблоны материалов

Здесь хранятся общие образцы оформления шпаргалок и практических страниц.
Они задают структуру; техническое содержание проверяется для каждой темы отдельно.

- [Шаблон шпаргалки и подробной страницы](cheat-sheet.md)
- [Правила для агентов](../AGENTS.md)
- [Все материалы](../README.md)

При создании темы замени подсказки конкретным содержанием и убери неиспользуемые части.
Рабочие примеры инструментов размещай в соответствующем тематическом разделе, а не здесь.

## Выбор формата

| Объём и назначение | Размещение |
| --- | --- |
| Компактный справочник | Один файл с тремя уровнями |
| Справочник и несколько длинных примеров | Каталог с `README.md` и `recipes.md` |
| Много независимых сценариев | `README.md` и страницы по задачам: `testing.md`, `deployment.md` и т. п. |

У крупной темы `README.md` остаётся краткой точкой входа. Подробности группируются по задачам,
а уровень указывается на каждой подробной странице. Длина файла сама по себе не задаёт границу.
Для навигации используй относительные ссылки и обычные якоря заголовков GitHub.

## Подробная страница

Подробная страница имеет один H1 с названием задачи и ссылку на `README.md` темы.
Для самостоятельного сценария используй следующий порядок; в сборнике повторяй его для каждого рецепта:

1. Уровень, задача и необходимые знания.
2. Зависимости, подготовка окружения и исходные данные.
3. Полный пример или последовательность шагов с указанием языка и места выполнения.
4. Команда проверки и ожидаемый результат.
5. Ограничения, очистка учебных ресурсов при необходимости, официальный источник.

В паспорте страницы раздели выполненные сценарии и сверенные по документации.
Если страница охватывает несколько уровней, подпиши уровень каждого рецепта.
Для большого сборника составь оглавление; самостоятельные задачи вынеси в файлы с предметными именами.
