## Как повторить проверку

1. Получите список файлов командой `git ls-files -co --exclude-standard`. При подсчёте пропустите сам отчёт. Включите Markdown, конфигурацию, исходники, лицензии, иллюстрации и архивные снимки.
2. Соберите адреса HTTP(S) с путём и фрагментом. Сопоставьте их со ссылками, изображениями и HTML-атрибутами в разборе CommonMark с таблицами. В итоговом рабочем дереве парсер насчитал 1 852 переходов Markdown к внешним ресурсам. Ещё восемь ссылок Markdown ведут к локальным учебным серверам. URL из команд, конфигурации и снимков GitHub учитывались отдельно. Добавьте четыре адреса из [лицензии CC BY](../../LICENSES/CC-BY-4.0.txt), подставив HTTPS.
3. Отделите учебные адреса. В исходном дереве 124 упоминания относились к 43 разным учебным адресам. Среди них localhost, имена сервисов Compose и специально несуществующие домены. В 15 SVG адрес пространства имён задаёт формат XML. Для этих значений сетевой запрос не проверяет назначение материала.
4. Сохраните параметры запроса. Удалите только фрагмент. Выполните GET с переходом по HTTP-перенаправлениям. Например, `curl -sSL --compressed --max-time 25 -o page.html -w '%{http_code} %{url_effective}\n' "$url"`. Проверьте заголовок и содержимое ответа. При отказе повторите запрос и сверьте страницу у издателя другим способом.
5. Найдите декодированный фрагмент среди атрибутов HTML `id` и `a[name]`. Учтите префикс `user-content-` в разметке GitHub. Для пяти диапазонов GitHub проверьте номера строк в исходном файле на указанном коммите. Для трёх Markdown-файлов используйте `?plain=1`. Подсветку строк в браузере отдельно не проверяли.

При обходе использовали Python 3.14.7, markdown-it-py 4.2.0 и curl 8.7.1. Запросы к одному хосту выполняли последовательно. Все внешние фрагменты (93) соответствуют HTML-якорю или существующему диапазону строк в исходнике.
