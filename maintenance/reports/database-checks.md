## PostgreSQL — 6 ноября

Целевая ветка документации — PostgreSQL 18; сверены release notes 18.6.
В PostgreSQL 18.6 / PGlite 0.5.15, WebAssembly в памяти, выполнены 12 SQL-блоков темы.
Пять групп проверили JOIN/суммы, rollback, окна, JSONB/FTS, четыре индекса, откат партиций и materialized view.
Это не исполнение всех фрагментов на нативном сервере.

[Полный backup-сценарий](../../docs/ru/databases/relational/postgresql/backup-lab.md) выполнен отдельно на нативном PostgreSQL 18.6.
Сервер, `pg_dump`, `pg_restore`, `psql` и `createdb` имели одну версию.
Среда: одноразовый Debian Linux arm64 контейнер, Bash 5.2.37, без внешней сети и опубликованных портов.
Запущен `bash backup-lab.sh` с исходным `queries.sql` и проверками `verify-backup.sql` из Markdown.

| Сценарий | Фактический результат |
| --- | --- |
| Custom и plain restore в новые учебные БД | Данные совпали; FK/CHECK/UNIQUE и identity проверены |
| Занятое имя любой создаваемой БД | Цепочка остановилась; существующие данные и identity-последовательности сохранены |
| Ошибочный data-only restore | Изменения откатились |

После ревью дополнительные пробы подтвердили сохранность существующих данных для custom/plain.
Контейнер после проверки удалён.
Рабочие владельцы и ACL намеренно исключены через `--no-owner --no-privileges`.
Параллельный restore, RLS, расширения, другие major-версии, конкурентный DDL, PITR и аварийное восстановление не проверялись.
Серверные службы, права рабочих ролей, блокировки и производительность не настраивались и не измерялись.

### Исправление TTL-карточки — 8 ноября

Независимое ревью выявило P2: `SET KEEPTTL` создавал бессрочный ключ, если прежний ключ исчез.
[Карточка](../../docs/ru/databases/non-relational/redis/data-and-caching.md#обновить-значение-и-сохранить-срок) исправлена на `xx=True, keepttl=True` с обработкой `None`.
`XX` не проверяет наличие TTL; конкурентный `PERSIST` требует отдельного атомарного протокола.
Полный `data.py` не менялся.

Среда адресной проверки: macOS arm64, Python 3.14.6, Redis 8.2.11, redis-py 8.1.0.
Redis собран во временной папке с `MALLOC=libc BUILD_TLS=no`; системная служба не устанавливалась.
Точный блок карточки извлечён из Markdown и выполнен через собственный Redis без TCP/persistence.
Обёртка клиента удаляла собственный ключ непосредственно перед вторым SET.

| Проверка | Фактический результат |
| --- | --- |
| Прежняя карточка и удаление между командами | `AssertionError` на TTL; дефект воспроизведён |
| Исправленная карточка, volatile-ключ существует | `True`, новое значение Ada Lovelace; PEXPIRETIME прежний, PTTL положителен |
| Исправленная карточка, ключ удалён | `None`, новый ключ не создан, TTL=-2; сообщение об отсутствии ключа |
| Очистка | Собственный Redis остановлен; временный каталог с сокетом удалён |

Команда проверки: `/tmp/redis-ttl-card-check/venv/bin/python /tmp/redis-ttl-card-check/check_card.py`, код 0.
Рецензент принял исправление узкой повторной проверкой; полного Redis-набора не повторял.
Реальное истечение таймера, eviction, конкурентный PERSIST и восстановление после сбоя отдельно не воспроизводились.

10 ноября серверные программы не запускались: проверены сохранность блоков, якоря и синтаксис.
