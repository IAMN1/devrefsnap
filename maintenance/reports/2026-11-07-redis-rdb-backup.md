Программа не принимает адрес действующего Redis и не заменяет файлы существующих экземпляров.

## Сверка с официальными источниками

Дата сверки: 7 ноября 2026.
Целевая ветка: Redis Open Source 8.2; исполнение на 8.2.11.

- [Redis persistence](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/) — готовый RDB можно копировать, файл публикуется после завершения снимка; AOF имеет приоритет при одновременном использовании.
- [BGSAVE](https://redis.io/docs/latest/commands/bgsave/) — фоновое создание снимка; ответ команды не означает завершение записи.
- [EXPIRE](https://redis.io/docs/latest/commands/expire/) — абсолютные моменты истечения и зависимость от часов машины.
- [PEXPIRETIME](https://redis.io/docs/latest/commands/pexpiretime/) — абсолютный момент истечения в миллисекундах Unix-времени.
- [Redis 8.2.11 release notes](https://github.com/redis/redis/releases/tag/8.2.11) — просмотрено исправление безопасности выбранного выпуска; оно относится к большим сообщениям в Cluster, который сценарий не запускает.
- [rdb.c в теге 8.2.11](https://github.com/redis/redis/blob/8.2.11/src/rdb.c) — в локальных исходниках выбранного выпуска проверены сохранение EXPIRETIME_MS и пропуск просроченных ключей при загрузке standalone.

Сайт документации возвращал ошибку для PTTL и каталога команд 8.2.
Поэтому ответы PTTL дополнительно проверены исполнением на 8.2.11, а формат сохранения срока — по исходникам этого выпуска.
Текстовые источники и реальные запуски учитываются отдельно.

Каждый запуск создавал собственный `/tmp/redis-rdb-*` с синтетическими данными.

В предварительном запуске обнаружено, что redis-cli выводит INFO как текст даже с --json.
Причина подтверждена в `redis-cli.c` версии 8.2.11: INFO принудительно выбирает raw-вывод.
Помощник исправлен: INFO обрабатывается отдельно от JSON-ответов остальных команд.

## Существенные ограничения

- Пример создаёт только маленький набор данных в БД 0; другие логические БД и модули не проверены.
- Оба процесса используют одинаковые бинарные файлы Redis; совместимость разных версий не проверялась.
- Linux указан как целевая среда с Unix-сокетами; фактическое выполнение проведено на macOS.
- Конкурентные записи во время BGSAVE, нехватка диска, повреждение RDB, AOF, Cluster и аварийное восстановление не проверялись.
- Проверка AssertionError подтверждает очистку при ошибке программы, а не устойчивость к сбою питания.
- Часы не переводились; перенос между компьютерами с рассинхронизацией не проверен.
- Учебная копия остаётся на том же компьютере; удалённое хранение, retention, шифрование и восстановление в рабочую службу не настроены.
- Остальные сценарии Redis, SQLAlchemy, FastAPI и резервных копий не перезапускались.
