# Проверка RDB-копии Redis — 2026-11-07

[Полный сценарий](../../databases/non-relational/redis/backup-and-restore.md) извлечён из Markdown как `rdb_backup.py`.
Среда: macOS arm64, Python 3.14.7, Redis server и redis-cli 8.2.11.
Использованы учебные бинарные файлы `/private/tmp/cheat-sheet-redis-build/redis-8.2.11/src/`.
Программе достаточно стандартной библиотеки Python.

## Сценарий и результаты

`python rdb_backup.py` дважды завершился кодом 0, включая контрольный запуск точного блока Markdown.
Каждый запуск создавал собственные source/restored через разные Unix-сокеты в новом каталоге `/tmp/redis-rdb-*`.
TCP, AOF и автоматические сохранения отключены; действующие службы и их файлы не использовались.

Предварительный запуск выявил, что `redis-cli --json INFO` всё равно выдаёт raw-текст.
Поведение подтверждено в `redis-cli.c` 8.2.11; INFO разбирается отдельно от JSON остальных команд.

| Проверка | Фактический результат |
| --- | --- |
| BGSAVE | Завершён; `rdb_last_bgsave_status=ok`; dump.rdb непуст |
| Три копии RDB | SHA-256 источника, backup.rdb и файла восстановления совпал |
| Строка | Восстановлено `before snapshot`, а не позднее `after snapshot` |
| Hash и list | id=42, name=Alice; порядок first, second сохранён |
| Постоянные ключи | PTTL=-1 для строки, hash и list |
| Живой временный ключ | Значение сохранено; PEXPIRETIME прежний, PTTL положителен и уменьшился |
| Просроченный ключ | Отсутствует после простоя; PTTL=-2 |
| Поздняя запись | Созданный после снимка ключ отсутствует; всего четыре ключа в БД 0 |
| Очистка | Оба своих процесса завершены через SHUTDOWN NOSAVE |
| `python -O` | Отказ до создания каталога и процессов |
| Неверное ожидаемое значение | `AssertionError`; оба Popen завершены, сокеты удалены |

PTTL в двух запусках: 119991 → 114857 мс и 119992 → 114881 мс.
Условия: один компьютер, исходный TTL 120 секунд, ожидание истечения другого ключа с TTL 5 секунд.
Числа показывают течение времени при простое; производительность не измерялась.
Негативная проверка меняла только ожидаемую строку во временном коде, без повреждения RDB.

## Сверка и границы

7 ноября сверены [persistence](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/), BGSAVE, EXPIRE, PEXPIRETIME и release notes 8.2.11.
Формат EXPIRETIME_MS и пропуск просроченных ключей дополнительно проверены по [rdb.c 8.2.11](https://github.com/redis/redis/blob/8.2.11/src/rdb.c).
Документация PTTL не загрузилась; ответы PTTL проверены исполнением, а формат срока — по исходникам выбранного выпуска.
Python скомпилирован; ссылки и ограждения проверены; схема разобрана Mermaid 11.17.2.
Независимое ревью проверило изоляцию, BGSAVE, cleanup и смысл assertions без замечаний.
Рецензент не повторял полный Redis-запуск.

- Проверена только маленькая БД 0 на одинаковых бинарных файлах источника и цели.
- Linux с Unix-сокетами указан как цель; фактическое выполнение было на macOS.
- Конкурентные записи при BGSAVE, повреждение RDB, нехватка диска, AOF, Cluster и сбои питания не проверялись.
- Перевод часов, рассинхронизация компьютеров, другие версии и модули не проверялись.
- Копия оставалась на том же компьютере; удалённое хранение, retention, шифрование и восстановление рабочей службы не настраивались.
- Проверка AssertionError подтверждает очистку при ошибке программы, а не аварийное восстановление.
