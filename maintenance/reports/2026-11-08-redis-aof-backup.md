# Проверка AOF-копии Redis — 2026-11-08

[Полный сценарий](../../databases/non-relational/redis/aof-backup-and-restore.md) извлечён из Markdown как `aof_backup.py`.
Среда: macOS arm64, Python 3.14.7, Redis server и redis-cli 8.2.11; только стандартная библиотека Python.
Официальный архив 8.2.11 собран во временном каталоге с `MALLOC=libc BUILD_TLS=no`.
Системная служба Redis не устанавливалась.

## Сценарий и результаты

`python aof_backup.py` дважды завершился кодом 0, включая контрольный запуск точного блока Markdown.
Созданы собственные source/restored через Unix-сокеты в закрытом `/tmp/redis-aof-*`; TCP и автоматические RDB-снимки отключены.
AOF: `appendfsync always`, `auto-aof-rewrite-percentage 0`, `aof-use-rdb-preamble yes`, `aof-load-truncated no`.
Это настройки маленького учебного набора.
Источник штатно остановлен до копирования; проверен сценарий с недоступностью источника, без online backup.

| Проверка | Фактический результат |
| --- | --- |
| BGREWRITEAOF | in_progress=0, scheduled=0, last_bgrewrite_status=ok |
| SHUTDOWN NOSAVE | Источник завершился успешно до копирования |
| Manifest и файлы | Одна BASE RDB, непустая INCR и manifest; все указанные файлы существуют |
| Дополнительные поля | startoffset/endoffset не мешают разбору имён, ролей и номеров |
| Отдельный dump.rdb | Отсутствует; base.rdb является частью AOF |
| Побайтовая копия | SHA-256 всех файлов совпал у источника, backup и цели до запуска |
| BASE → INCR | Строка `after rewrite`; hash id=42/name=Alice; list first, second, third |
| Постоянные ключи | PTTL=-1 для строки, hash и list |
| Живой временный ключ | Значение и PEXPIRETIME сохранены; PTTL положителен и уменьшился |
| Просроченный ключ | Отсутствует; PTTL=-2; всего четыре ключа БД 0, AOF включён |
| `python -O` | Отказ до создания каталога и процессов |
| Удаление manifest, BASE или INCR | Каждый неполный набор отклонён до запуска Redis |
| Дописанные байты INCR | Несовпадение SHA-256 обнаружено до передачи файла серверу |
| Неверное ожидаемое значение | `AssertionError`; оба своих процесса остановлены, сокеты удалены |

Получены `appendonly.aof.2.base.rdb`, `appendonly.aof.2.incr.aof`, `appendonly.aof.manifest`.
Номер поколения не зашит в программу.
PTTL: 119979 → 114856 мс и 119978 → 114839 мс.
Условия: один компьютер, TTL 120 секунд, ожидание другого ключа с TTL 5 секунд после остановки источника.
Числа показывают течение времени; производительность не измерялась.
Отрицательные проверки меняли только отдельные временные копии.

## Сверка и границы

8 ноября сверены persistence, BGREWRITEAOF, SHUTDOWN, EXPIRE, PEXPIRETIME и release notes 8.2.11.
BASE → INCR и поля manifest подтверждены по [aof.c 8.2.11](https://github.com/redis/redis/blob/8.2.11/src/aof.c).
Flush/fsync при SHUTDOWN независимо от NOSAVE проверены по [server.c 8.2.11](https://github.com/redis/redis/blob/8.2.11/src/server.c).
Документация latest дополнена исходниками выбранного выпуска; новые API других веток не включались.
Ссылки, Python-компиляция, Bash-синтаксис и ограждения проверены.
Независимое ревью проверило inventory на двух сохранённых копиях, включая дополнительные поля manifest.
Блокирующих замечаний не найдено.
Рецензент не повторял полный Redis-запуск; Mermaid проверена редакторски без парсера.

- Online backup, конкурентные записи, другие версии и модули не проверялись.
- Набор ограничен БД 0; inventory не является универсальным парсером manifest.
- Несколько INCR после неуспешного rewrite и historical-файлы не проверялись.
- Повреждённый или оборванный INCR не загружался сервером; автоматический ремонт не выполнялся.
- Сбои питания, нехватка диска, fsync-ошибки, Cluster и отказ оборудования не воспроизводились.
- Linux с Unix-сокетами указан как цель; фактическое выполнение было на macOS.
- Часы не переводились; рассинхронизация машин, удалённое хранение, retention и шифрование не проверялись.
