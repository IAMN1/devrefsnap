# Пилот Co-op Translator на SQLAlchemy N+1

2026-11-11. База справочника `8bbe592`, Co-op Translator `0.24.0`, Python `3.14.7`, macOS arm64. Провели отдельные прогоны RU → EN и EN → RU на копиях обеих страниц. [Страница RU](../../docs/ru/python/databases/sqlalchemy/n-plus-one.md) · [Страница EN](../../docs/en/python/databases/sqlalchemy/n-plus-one.md) · [Релиз Co-op Translator](https://github.com/Azure/co-op-translator/releases/tag/v0.24.0).

Автоматическая запись в `docs/ru/` и `docs/en/` через штатный проектный режим может заменить правку участника без сообщения о конфликте. В обоих полных черновиках потребовалось бы восстановить навигацию.

## Как проверяли

- Выполнили `translate --dry-run --plan-json` с `--source` на исходный языковой каталог, `--output` на общий `docs/` и `--include python/databases/sqlalchemy/n-plus-one.md`. В обоих планах уже существующая целевая страница без метаданных получила статус устаревшей. [CLI v0.24.0](https://github.com/Azure/co-op-translator/blob/v0.24.0/docs/cli.md).
- В исходной странице уточнили, что чтение незагруженной коллекции постов выполняет отдельный `SELECT` даже для пользователя без постов. В целевой странице независимо переформулировали тот же абзац и уточнили срок жизни учебных данных в другом абзаце.
- Прямой запуск `translate` с OpenAI-совместимым адресом локального Ollama остановился на проверке подключения. Для проверки записи и метаданных вызвали `run_translation` с теми же путями. Подменили проверку подключения и ответ модели в процессе Python. Контрольный ответ переводил тестовую фразу и сохранял служебные маркеры.
- Два полных черновика получили через `start_markdown_agent_translation` и `finish_markdown_agent_translation`. Каждый документ дал один фрагмент. Его перевела установленная модель Ollama `qwen3.5:9b` (`6488c96fa5fa`) через локальный `/api/chat`. Сохранили ответы отдельно от справочника. [Агентный API v0.24.0](https://github.com/Azure/co-op-translator/blob/v0.24.0/docs/mcp.md#translate-with-the-host-agent-model).

## Ручные правки и конфликт

| Сценарий | Результат в обе стороны |
| --- | --- |
| Проектный режим, существующий перевод без метаданных | Целевой файл перезаписан целиком. Исчезли обе ручные правки |
| Повторный запуск с метаданными и прежним источником | `run_translation` вернул `(0, 0)`. Ручная правка цели сохранилась |
| Новая правка источника после синхронизации | `run_translation` вернул `(1, 0)`. Целевая правка исчезла. Журнал показал `file_completed`, события о конфликте не было |
| Дополнительная устаревшая страница за пределами `--include` | `scope-control.md` тоже перезаписан. В первом проходе обработаны два файла |
| Алгоритм `TranslationStateProvider` с текущей парой страниц | 32 блока в RU, 29 в EN. `build_incremental_markdown` вернул `full` с причиной `baseline_structure_mismatch` |
| Тот же алгоритм на выровненном фрагменте N+1 | Сохранил ручную правку в другом блоке. При правке одного блока в обеих версиях заменил целевой текст. Режим `incremental`, два блока сохранены, один переведён, причины отказа нет |

В проектном API ветка `full` вызывает перевод всего файла. Запись результата происходит до вызова `record_candidate`. Для остановки при конфликте сравнение обеих страниц с принятой парой нужно выполнять до передачи целевого пути проектному переводу. [Алгоритм по блокам](https://github.com/Azure/co-op-translator/blob/v0.24.0/src/co_op_translator/core/project/translation/incremental_markdown.py#L136-L228) · [Порядок записи](https://github.com/Azure/co-op-translator/blob/v0.24.0/src/co_op_translator/core/project/translation/project_markdown_translation.py#L256-L318) · [Обновление устаревших файлов](https://github.com/Azure/co-op-translator/blob/v0.24.0/src/co_op_translator/core/project/translation/translation_maintenance.py#L20-L86).

## Код, ссылки и якоря в полных черновиках

| Проверка | RU → EN | EN → RU |
| --- | --- | --- |
| Ограждённые блоки `python`, `bash`, `text` | 3 из 3 совпали побайтно | 3 из 3 совпали побайтно |
| Вставки кода в строках | Сохранены все 49 | Сохранены все 45 |
| Ссылки на общий `n_plus_one.py` и внешние источники | Оба пути к примеру и все 6 внешних адресов сохранились | Оба пути к примеру и все 6 внешних адресов сохранились |
| Ссылка на другую языковую версию | После подстановки черновика ведёт на текущую страницу | После подстановки черновика ведёт на текущую страницу |
| Якоря при проверке всей копии `check_materials.py` | 6 ошибок. Четыре ссылки внутри страницы и две входящие ссылки | 13 ошибок. Четыре ссылки внутри страницы, одна ссылка в соседний файл и восемь входящих ссылок |

Например, в английском черновике заголовок стал `Why N+1 occurs`, а ссылка сохранила `#почему-возникает-n1`. В русском черновике сохранился `relationship-loading.md#choose-a-strategy`, хотя целевой файл использует `#выбрать-стратегию`. Ссылка на саму страницу формально указывает на существующий файл, поэтому её проверили отдельно.

`co-op-review` в обоих черновиках сообщил об отсутствии метаданных. Для EN → RU он также выдал предупреждение об одном неизменившемся блоке. Ошибки якорей обнаружил проверяющий код справочника. В агентном режиме функции подготовки и сборки черновика не создают проектные метаданные. [Режимы Co-op Translator](https://github.com/Azure/co-op-translator/blob/v0.24.0/docs/agents.md#choose-who-makes-the-model-calls).

При чтении черновиков сверили технический смысл тестовой правки и вывод примера. Оба черновика передали отдельный `SELECT` для пользователя без постов. Формулировку «ленивая загрузка выпускает отдельный SELECT» стоит отредактировать. Фраза «подтверждает выборочные строки» искажает смысл `with session.begin()`. При успешном завершении блок фиксирует изменения.

Хеш общего `n_plus_one.py` совпал с базой. Отдельно запустили этот файл на Python `3.14.7` и SQLAlchemy `2.1.8` с SQLite в памяти. Пример вернул `lazy: 3 SELECT` и `selectinload: 2 SELECT` с одинаковыми данными. [Общий файл примера](../../examples/python/databases/sqlalchemy/n_plus_one.py).

## Охват дальнейших проверок

Проверка способа синхронизации требует повторения на нескольких представительных страницах. Для рабочего обновления определяйте изменённые пары по Git и проверяйте их черновики. Статическую проверку ссылок и якорей запускайте на всём дереве, чтобы проверить входящие ссылки с других страниц. Исторические адреса, служебные файлы и редакторские образцы требуют отдельного решения об охвате при любом массовом запуске.

В очереди остаётся проверка способа, который сохраняет обе независимые правки до ревью и явно показывает конфликт. [Очередь работ](../plans/README.md#согласованный-порядок-следующих-этапов).
