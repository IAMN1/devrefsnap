## Как читать схемы

| Представление | На какой вопрос отвечает | Что означает связь |
| --- | --- | --- |
| Дерево исходников `text` | Где могут лежать роли? | Вложенность каталогов; это возможный вариант размещения |
| Зависимости кода | Кто знает чей API? | Подписанный импорт/использование контракта; пунктир может означать структурное соответствие |
| Последовательность вызовов | Кто кого вызывает во время работы? | Вызов, ответ или передача сообщения |
| Развёртывание | Что работает и выпускается отдельно? | Локальная либо сетевая связь между исполняемыми частями |

Одна программа может иметь слои в одном процессе.
Программа может вызывать адаптер без импорта его класса в прикладном модуле.
Название паттерна не задаёт обязательного дерева каталогов.

## Маршрут повторения

- [ ] **Базовый:** назовите проблему — [принципы](principles.md#базовый-уровень).
- [ ] **Базовый:** определите контракт — [контракт и инвариант](principles.md#контракт-и-инвариант), [S / O](solid.md#базовый-уровень).
- [ ] **Средний:** сравните варианты на одном изменении — [паттерны кода](patterns/design-patterns.md), [структуры пакетов](patterns/architecture-patterns.md#организация-кода).
- [ ] **Продвинутый:** проверьте замену реализации — [L / DIP](solid.md).
- [ ] **Продвинутый:** проверьте частичный отказ — [распределённые сценарии](patterns/distributed-systems.md).

Принцип помогает оценить решение.
Паттерн предлагает известную форму решения.
Тест проверяет конкретное поведение.
Успех локального примера не доказывает пригодность архитектуры для любой нагрузки и команды.
