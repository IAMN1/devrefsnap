## Базовый уровень

**Начните с того, что меняется.** Алгоритм, формат внешнего API, дополнительное поведение,
создание, подписка и представление запроса решают разные задачи.
[Шпаргалка паттернов кода](design-patterns.md) показывает роли и вызовы всех шести приёмов.

Strategy в Python может быть callable, Adapter — функцией преобразования, Factory — функцией сборки.
Один простой вариант часто удобно оставить прямой функцией; иерархия классов не обязательна.

## Продвинутый уровень

**Начните с частичного отказа.** Перед разделением на процессы определите владение данными,
возможные исходы и протокол повтора. [Карточки распределённых сценариев](distributed-systems.md)
показывают гарантию и её границу, а [полный Outbox](distributed-systems.md#полный-пример-outbox-и-дубликат-публикации)
— rollback локальной записи и дубликат публикации.

- [ ] Названо, что остаётся сохранённым после сбоя.
- [ ] Описаны повтор, неизвестный исход и возможный двойной эффект.
- [ ] Указано, кто наблюдает и исправляет застрявший процесс.

## Частые ошибки

| Смешение | Уточнение |
| --- | --- |
| Ports & Adapters = microservices | Границы приложения и единицы развёртывания — разные оси |
| `@decorator` = любой Decorator pattern | Синтаксическая обёртка и объектный паттерн связаны по идее, но не тождественны |
| Factory = обязательно Abstract Factory / Factory Method | Простая функция сборки не обязана реализовывать эти GoF-паттерны |
| CQRS = Event Sourcing | Разделение моделей чтения/записи не требует событий как источника истины |
| Retry = повторять любую ошибку | Нужны классификация, общий лимит времени и безопасная семантика повтора |
