## Базовый уровень

**Начните с того, что меняется.**
Алгоритм, формат внешнего API и дополнительное поведение решают разные задачи.
Создание, подписка и представление запроса тоже решают разные задачи.
[Шпаргалка паттернов кода](design-patterns.md) показывает роли и вызовы всех шести приёмов.

Strategy в Python может быть callable.
Adapter может быть функцией преобразования.
Factory может быть функцией сборки.
Один простой вариант часто удобно оставить прямой функцией.
Иерархия классов не обязательна.

Проверьте сценарий без внешней службы.

## Продвинутый уровень

**Начните с частичного отказа.**
Перед разделением на процессы определите владение данными.
Определите возможные исходы.
Задайте протокол повтора.
[Карточки распределённых сценариев](distributed-systems.md) показывают гарантию и её границу.
[Полный Outbox](distributed-systems.md#полный-пример-outbox-и-дубликат-публикации) показывает rollback локальной записи и дубликат публикации.

- [ ] Укажите, что остаётся сохранённым после сбоя.
- [ ] Опишите повтор.
- [ ] Опишите неизвестный исход.
- [ ] Опишите возможный двойной эффект.
- [ ] Укажите, кто наблюдает за застрявшим процессом.
- [ ] Укажите, кто исправляет застрявший процесс.

## Частые ошибки

| Смешение | Уточнение |
| --- | --- |
| Ports & Adapters = microservices | Границы приложения и единицы развёртывания — разные оси |
| `@decorator` = любой Decorator pattern | Синтаксическая обёртка и объектный паттерн связаны по идее, но не тождественны |
| Factory = обязательно Abstract Factory / Factory Method | Простая функция сборки не обязана реализовывать эти GoF-паттерны |
| CQRS = Event Sourcing | Разделение моделей чтения/записи не требует событий как источника истины |
| Retry = повторять любую ошибку | Нужны классификация, общий лимит времени и безопасная семантика повтора |
