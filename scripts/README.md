# Статические проверки материалов

Используйте эти инструменты для проверки оформления, локальной навигации и синтаксиса.
Учебный код остаётся данными. Инструменты не проверяют правильность советов или безопасность команды при выполнении.

## Запустить локально

Для Linux x86_64 создайте отдельное окружение с Python 3.13.
Для macOS arm64 замените первую команду на `python3.14 -m venv /tmp/cheat-sheet-ci`.
Хеши PyYAML закреплены для этих двух сочетаний платформы и Python.
Установите закреплённые зависимости из PyPI.

```bash
python3.13 -m venv /tmp/cheat-sheet-ci
/tmp/cheat-sheet-ci/bin/python -I -m pip install --require-hashes --only-binary=:all: -r scripts/requirements-ci.txt
/tmp/cheat-sheet-ci/bin/python -I scripts/check_materials.py
/tmp/cheat-sheet-ci/bin/python -I -m unittest discover -s scripts/tests -v
```

Проверка возвращает код `0`, если ошибок нет.
Код `1` означает обнаруженную ошибку материала.
Каждая строка результата содержит JSON; последняя строка содержит счётчики.
Фактические версии локального прогона находятся в [отчёте CI](../maintenance/reports/2026-11-10-safe-ci.md).

Проверка читает Markdown и файлы `.py` и `.sh` в `examples/`.
Проверка пропускает `.git/`, `.venv/` и `__pycache__/`.
Проверка отклоняет символьные ссылки, файл больше 1 MiB и общий объём материалов больше 20 MiB.
Общий предел составляет 2000 проверяемых файлов.

| Проверка | Что подтверждает | Ограничение |
| --- | --- | --- |
| Ссылки | Существование локального файла или README каталога | Внешние адреса не запрашиваются |
| Якоря | Заголовки CommonMark, повторные заголовки и HTML `id`/`name` | Сложные расширения GitHub и отдельные символы Unicode могут требовать доработки |
| Ограждения | Закрытие и известный язык | Вложенные примеры внутри `markdown` остаются текстом |
| Python | Компиляция блоков и файлов `examples/` без исполнения | Верхнеуровневый `await` допустим в блоке Markdown. Импорты и зависимости не проверяются |
| Bash | Разбор блоков и файлов `.sh` через `/bin/bash -n` | Профили и переменные запуска не загружаются; другие shell не проверяются |
| Тесты проверяющего кода | Ошибки, границы путей, отсутствие исполнения контрольных фрагментов | Проверяющий код из PR также требует ревью |

Присвойте непроверяемому выводу язык `text`.
Не меняйте язык исполняемого примера ради обхода синтаксической ошибки.
Добавьте язык в список проверяющего кода, если новый материал требует дополнительного формата.
Полные примеры и базы данных проверяйте отдельно в учебном окружении с синтетическими данными.

## Прочитать сигналы ревью

Сравните текущий коммит с существующим базовым коммитом.
Передайте полный SHA в параметре `--base`.

```bash
base_sha=$(git rev-parse origin/main)
/tmp/cheat-sheet-ci/bin/python -I scripts/review_signals.py --base "$base_sha"
```

Сигналы выделяют добавленные адреса, зависимости, сетевые операции, отключение TLS и команды с существенными последствиями.
Изменения критических файлов выделяются также при удалении содержимого.
Указанные строки относятся к новой версии файла.
Сигналы не блокируют PR и не доказывают вредоносность.
`rm`, `chmod` и `git restore` могут быть частью правильного учебного рецепта.
Регулярные выражения могут пропустить замаскированную операцию или новый способ установки.
Проверьте смысл всего изменения, включая файлы без сигналов.

## Проверить внешний PR

1. Откройте **Files changed** и прочитайте diff до разрешения запуска.
2. Проверьте `.github/`, `scripts/`, `AGENTS.md`, `templates/` и CODEOWNERS.
3. Проверьте новые адреса, пакеты, скачивание скриптов, передачу данных и условия разрушительных команд.
4. Если изменения готовы к запуску, откройте **Awaiting approval** и нажмите **Approve workflows to run**.
5. Дождитесь `materials-static` и `checker-tests` на последней версии PR.
6. Если `main` изменилась, обновите ветку PR и дождитесь новых проверок.
7. Сопоставьте проверенный SHA с коммитом, который собираетесь слить.

Actions использует `pull_request` и `push` в `main`, одноразовый GitHub-hosted runner и токен `contents: read`.
Workflow не сохраняет Git credentials, не использует секреты, кэши, артефакты или рабочие базы данных.
Каждое задание ограничено пятью минутами; проверяющие процессы ограничены 120 секундами CPU и 2 GiB виртуальной памяти.
Runner имеет сетевой доступ для checkout, установки Python и зависимостей.
Это не изоляция сети от произвольно изменённого workflow или теста.
Не добавляйте к этому процессу секреты или привилегированную обработку артефактов.
Не запускайте изменённые скрипты внешнего PR на рабочем компьютере до ревью.

Для `main` действует [Protect main](https://github.com/IAMN1/devrefsnap/rules/27309604).
GitHub требует PR и обе проверки Actions на актуальной базе.
Правило запрещает force push и удаление ветки. Список обхода пуст.

В CODEOWNERS указаны критические файлы для ручного ревью владельцем.
Число обязательных одобрений равно нулю, поэтому единственный сопровождающий может слить свой PR после CI.
Внешний участник отправляет PR из форка. Запуск его workflow требует разрешения сопровождающего.
