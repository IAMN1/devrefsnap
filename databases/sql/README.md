## Базовый уровень

Порядок `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY` помогает читать SELECT.
Это логическая модель.
Модель не задаёт планировщику физический порядок вычислений.
Сначала выполните [учебный пример](query-lab.md#полный-пример).
Затем меняйте по одному условию.

Фрагмент после этого примера, PostgreSQL/SQLite:

```sql
SELECT name FROM sql_users WHERE name LIKE 'a%' ORDER BY id;
```

Результат — `alice`. Чувствительность LIKE к регистру и правила сравнения текста зависят от СУБД/collation.
`SELECT *` удобен при исследовании.
В интерфейсах приложения обычно задавайте нужные столбцы явно.

## Средний уровень

[JOIN, EXISTS, группировки и обычные CTE](queries.md) объединяют несколько таблиц и этапов расчёта.
`WHERE` фильтрует строки до группировки.
`HAVING` фильтрует группы.
`COUNT(*)` считает строки.
`COUNT(column)` не считает NULL.
Внешний JOIN сохраняет несовпавшие строки, пока последующий фильтр не удалит эти строки.

Для изменений используйте параметры драйвера, ограничения и транзакции.
Одинаковое имя команды не означает одинаковые гарантии.
[DDL и TRUNCATE](dialects-and-transactions.md) различаются между СУБД.

## Продвинутый уровень

[Окна и рекурсивные CTE](queries.md#агрегация-cte-и-окна) нужны для накопительных итогов,
рангов и иерархий. Размер фрейма в строках отличается от интервала времени.
[Изоляция, планы и индексы](dialects-and-transactions.md) требуют измерений на целевой СУБД.
План для трёх строк не предсказывает поведение большой рабочей таблицы.

## Частые ошибки

| Ошибка | Что проверить |
| --- | --- |
| `column = NULL` | Используйте IS NULL / IS NOT NULL |
| NOT IN не вернул ожидаемые строки | NULL в подзапросе меняет логику; рассмотрите NOT EXISTS |
| LEFT JOIN потерял строки без совпадений | Фильтр правой таблицы в WHERE часто превращает результат в аналог INNER JOIN |
| UPDATE/DELETE затронул всё | Пропущен WHERE; до изменения проверьте SELECT с тем же условием |
| Нестабильная пагинация | Нужен ORDER BY с уникальным последним ключом; большой OFFSET может быть дорогим |
| «READ UNCOMMITTED везде одинаков» | В PostgreSQL он работает как READ COMMITTED |
| Копия SQL содержит AUTO_INCREMENT, MODIFY и RETURNING вперемешку | Выберите диалект; используйте [таблицу различий](dialects-and-transactions.md#различия-диалектов) |
