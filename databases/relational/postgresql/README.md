## Выполнить первый запрос

Начните с [подключения](operations.md#подключение-и-команды-psql).
Затем выполните [единый учебный пример](query-lab.md#полный-пример-учебная-база).
Пример создаёт три таблицы в схеме `demo`.
Пример показывает JOIN и проверяет откат изменения данных.

Фрагмент SQL, продолжение этого примера в БД `cheatsheet_demo`:

```sql
SELECT name, price
FROM demo.products
WHERE price >= 100
ORDER BY price DESC, id;
```

Ожидаются `Monitor | 300.00` и `Keyboard | 100.00`. Порядок результата задаёт `ORDER BY`.
Для пользовательских значений приложение использует параметры своего драйвера.
Подстановка строк в SQL не заменяет параметризованный запрос.

## Частые ошибки

| Симптом / заблуждение | Причина и действие |
| --- | --- |
| Команда `\dt` не работает в драйвере | Это команда `psql`, а не SQL; [контексты разделены](operations.md#подключение-и-команды-psql) |
| «READ UNCOMMITTED позволяет грязные чтения» | В PostgreSQL он работает как READ COMMITTED |
| Пагинация возвращает разные наборы | `LIMIT/OFFSET` без устойчивого `ORDER BY` не задаёт порядок; большой OFFSET также может быть дорогим |
| `GRANT … ON ALL TABLES` не дал доступ к новой таблице | Нужны default privileges роли, которая создаёт будущие объекты |
| `CHECKPOINT` считают проверкой целостности | Он принудительно создаёт контрольную точку WAL |
| `TRUNCATE` считают операцией без WAL или без отката | Очистка обычной таблицы журналируется и допускает откат; берётся ACCESS EXCLUSIVE, `CASCADE` затронет связанные таблицы |
| Восстановление настроено через `recovery.conf` | Файл не поддерживается с PostgreSQL 12; в 18 используются обычные параметры и signal-файлы |
