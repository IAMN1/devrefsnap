## Учебный экземпляр

Все Python-примеры используют обязательный REDIS_URL и случайный namespace `cheatsheet:{id}:`.
Примеры удаляют только явно созданные ключи.
FLUSHDB/FLUSHALL не нужны.
Выполняйте примеры на выделенном процессе с синтетическими данными.
Не используйте работающую системную службу.

После установки Redis откройте отдельный терминал.
Создайте временный каталог.
Запустите процесс на переднем плане с Unix socket, без TCP и persistence.
Ниже приведён полный пример оболочки.
Пример создаёт временные файлы без изменения настроек системной службы:

```bash
umask 077
redis_demo_dir="$(mktemp -d)"
printf 'Сокет учебного процесса: %s/redis.sock\n' "$redis_demo_dir"
redis-server --port 0 --unixsocket "$redis_demo_dir/redis.sock" --unixsocketperm 700 \
  --save "" --appendonly no --dir "$redis_demo_dir"
```

Дождитесь готовности процесса.
В другом терминале задайте REDIS_URL с **выведенным** путём.
Используйте форму `unix:///полный/путь/redis.sock?db=0`.
Не копируйте условный путь буквально.
Проверьте PING, например через `redis-cli -s /полный/путь/redis.sock PING`.
Ожидается PONG.
После завершения опытов остановите только этот процесс переднего плана через Ctrl-C.
Persistence отключён.
Данные процесса исчезнут при остановке.
Пример не является настройкой production.

## Сохранность и восстановление

| Механизм | Назначение | Что проверить |
| --- | --- | --- |
| RDB | Снимок состояния | Потеря изменений после последнего снимка; ресурсы fork/диска; восстановление файла на отдельном процессе |
| AOF | Журнал записей | appendfsync, ошибки диска, rewrite и multi-part AOF; при everysec возможна потеря примерно последней секунды при сбое |
| RDB + AOF | Совмещение способов | Что сервер загрузит при старте и как копируются все необходимые файлы |
| Репликация | Копия для чтения/доступности | Обычно асинхронна; failover может потерять подтверждённые записи |
| Backup вне экземпляра | Восстановление после удаления/аварии | Отдельное хранение, доступ, retention и регулярная проверка восстановления |

MULTI/EXEC не включает автоматически AOF/fsync.
WAIT позволяет ждать подтверждений реплик.
WAIT не гарантирует строгую согласованность и сохранение записи при любых отказах.
Реплика повторяет также ошибочные удаления.
Реплика не заменяет независимую резервную копию.
Наличие файла не доказывает пригодность копии.
Восстановите копию на отдельном экземпляре с совместимой версией.
Проверьте прикладные данные.

## Память и наблюдение

Задайте maxmemory с запасом для служебных расходов, persistence и репликации.
Выберите политику eviction под задачу.
При нехватке памяти noeviction отклоняет часть записей.
allkeys-lru/lfu вытесняют ключи.
volatile-политики выбирают только ключи со сроком.
TTL и eviction — разные причины исчезновения ключей.
Большие значения и команды с большим результатом увеличивают задержки.
Ограничьте размер pipeline.

Справочные команды Redis, не настройки для копирования целиком:

```text
INFO server
INFO memory
INFO persistence
INFO replication
INFO stats
SLOWLOG GET 5
LATENCY DOCTOR
```

Наблюдайте evicted_keys, expired_keys, попадания и промахи кеша, задержки, память, состояние AOF/RDB и отставание реплик.
Часть диагностики требует прав и предварительной настройки.
SLOWLOG может содержать аргументы команд.
Ограничьте доступ к SLOWLOG.
UNLINK откладывает освобождение памяти значения.
Отложенное освобождение памяти не отменяет удаление ключа.

## Репликация, Sentinel и Cluster

Sentinel наблюдает за репликацией и организует failover, а не шардирует данные.
Redis Cluster распределяет ключи по 16384 hash slots и требует клиента с поддержкой перенаправлений.
Hash tag в фигурных скобках позволяет совместно разместить связанные ключи.
Многоключевые операции и транзакции обычно требуют одного slot.
Cluster использует БД 0.
SELECT не разделяет арендаторов на разные cluster-БД.
Разбиение одного большого/горячего ключа автоматически не происходит от добавления shard.

## Доступ и безопасность

Ограничьте сеть и доступ к socket.
Protected mode не заменяет продуманные ACL.
В рабочем окружении используйте отдельные ACL users, минимальные категории команд и шаблоны ключей/каналов.
AUTH без TLS не шифрует сеть.
Для удалённого доступа настройте TLS и проверку сертификата.
Не помещайте секреты в публикуемые URL, команды и логи.
Административные CONFIG/DEBUG/SHUTDOWN/FLUSH* и чтение чужих ключей не нужны приложению кеша.
Не используйте просто номер логической БД как границу безопасности.
