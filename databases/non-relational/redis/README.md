# Redis

Redis — сервер структур данных в памяти.
Redis используют для кеша, счётчиков, множеств, ранжирования и сообщений.
Redis не заменяет реляционные ограничения.
Сохранность данных зависит от конфигурации и проверенного восстановления.

## Базовый уровень

Выберите структуру по операции.
Используйте string для значения или счётчика.
Используйте hash для полей объекта.
Используйте list для порядка, set для уникальности, sorted set для порядка по score.
[Первый сценарий](data-lab.md#полный-пример-структуры-и-ttl) создаёт только уникальные учебные ключи и удаляет их в finally.
Для этого сценария REDIS_URL обязателен.
По умолчанию код не подключается к Redis на компьютере.

## Средний уровень

[Кеш](data-and-caching.md#кеширование-cache-aside) требует политики инвалидирования, ограничения памяти и допустимой свежести.
TTL не гарантирует наличие ключа до указанного срока.
Приложение или eviction могут удалить ключ раньше.
Один INCR атомарен.
GET → вычисление → SET состоит из нескольких операций.
Для такого изменения нужен [WATCH/скрипт или другой протокол согласования](transactions-and-messaging.md).

## Продвинутый уровень

[Streams и Pub/Sub](transactions-and-messaging.md) имеют разные гарантии доставки.
[RDB/AOF, репликация и Cluster](operations.md) решают разные задачи.
Реплика не заменяет резервную копию.
Транзакция не гарантирует запись на диск.
Cluster не устраняет риск потери подтверждённой записи при сбое.
Примеры здесь используют standalone.
Эксплуатация Cluster/failover требует отдельного испытания.

## Частые ошибки

| Ошибка | Исправление |
| --- | --- |
| SET убрал TTL | Обычно замена значения удаляет TTL; используйте нужный EX/PX или KEEPTTL |
| TTL вернул -1 / -2 | -1: ключ без срока; -2: ключ отсутствует |
| Pipeline считают транзакцией | Пакетирование уменьшает ожидания, но само по себе не исключает вмешательство |
| EXEC откатит всё при ошибке | Runtime error одной команды не откатывает успешные команды транзакции |
| Pub/Sub используют как надёжную очередь | У отключённого подписчика нет истории; рассмотрите stream и обработку pending |
| KEYS/FLUSHALL в общем окружении | Используйте SCAN с ограничением. Удаляйте только явно свои ключи. FLUSHALL здесь не нужен |
| Redis открыт в интернет без ACL/TLS | Сначала ограничьте сеть, доступные команды/ключи и защиту соединения |
