# pytest

Запуск проверок поведения Python-программы: assertions, фикстуры, параметризация и плагины.
Несколько связанных утверждений могут проверять один сценарий; «один assert на тест» не является требованием pytest.

| Параметр | Значение |
| --- | --- |
| Проверенная ветка | pytest 9; отдельные возможности предоставляют плагины |
| Предпосылки | Python, изолированное окружение; базовое понимание функций и исключений |
| Сверено с документацией | 2026-11-06, pytest stable и официальные руководства используемых плагинов |
| Выполнено | 2026-11-06, CPython 3.14.7, pytest 9.2.0; версии плагинов и сценарии — [в проверках](configuration.md#что-проверено) |

## Быстрый поиск

Отдельные команды в каталоге тестового проекта; `python` должен принадлежать нужному окружению.

| Задача | Команда / API | Подробнее |
| --- | --- | --- |
| Запустить тесты | `python -m pytest` | [Конфигурация](configuration.md) |
| Конкретный тест | `python -m pytest test_basics.py::test_database_write` | [Полный пример](fixtures.md) |
| Подробный вывод | `python -m pytest -v` | [Отладка](configuration.md#выбор-тестов-и-отладка) |
| Подстрока имени / marker | `-k 'subtotal'` / `-m 'not slow'` | [Выбор тестов](configuration.md#выбор-тестов-и-отладка) |
| Ожидаемая ошибка | `pytest.raises(ValueError, match='quantity')` | [Assertions](fixtures.md) |
| Приближённое число | `pytest.approx(0.3)` | [Assertions](fixtures.md) |
| Временный путь / вывод | `tmp_path`, `capsys` | [Фикстуры](fixtures.md) |
| Подменить зависимость | `monkeypatch`, `mocker.patch` | [Моки](mocking-and-async.md) |
| Async-тест | `@pytest.mark.asyncio` + pytest-asyncio | [Async](mocking-and-async.md) |
| JUnit-отчёт | `--junitxml=report.xml` | [CI](configuration.md#плагины-и-отчёты) |

## Базовый уровень

### Написать осмысленный тест

Создай отдельное окружение: `python -m venv .venv`; установи в него `python -m pip install pytest`.
В uv-проекте удобнее `uv add --dev pytest` и `uv run pytest`; см. [uv](../../tooling/uv/README.md).
Тест содержит подготовку данных, действие и проверку наблюдаемого результата.
Он должен падать при неправильном поведении программы.

По умолчанию pytest ищет `test_*.py` / `*_test.py`, функции `test_*`, методы в классах `Test*`
без собственного `__init__`. `conftest.py` распространяет фикстуры на свой каталог и вложенные;
импортировать его вручную не нужно. Большой проект может размещать код в `src/package/`,
тесты в `tests/`; пакет должен быть установлен в тестовое окружение.

[Полный пример](fixtures.md) включает саму функцию, импорты, фикстуру БД и проверку ошибки входных данных.

## Средний уровень

### Управлять подготовкой и вариантами данных

Fixture по имени передаётся в аргумент теста. `yield` отделяет setup от teardown;
если setup падает до yield, код после yield этой fixture не выполняется.
Для нескольких ресурсов освобождай каждый сразу после его успешного создания отдельной fixture/контекстом.

```mermaid
flowchart LR
    A[Запрос fixture] --> B[Подготовка ресурса]
    B --> C[yield: передать тесту]
    C --> D[Тест: успех или исключение]
    D --> E[Teardown ресурса]
```

`@pytest.mark.parametrize` запускает независимые сценарии с конкретными ожидаемыми значениями.
`tmp_path`, `capsys`, `monkeypatch` помогают изолировать файлы, вывод и окружение.
[Примеры и границы scope](fixtures.md#область-действия-и-фабрики) позволяют избежать зависимости от порядка тестов.

## Продвинутый уровень

### Проверять границы без реальных внешних сервисов

Подменяй сеть или внешний адаптер в месте, где тестируемый модуль ищет объект.
Проверяй результат для пользователя и существенный контракт вызова; не закрепляй произвольное число
внутренних вызовов. [Моки и async](mocking-and-async.md) содержат реальные тесты без HTTP-запросов.

[Конфигурация и плагины](configuration.md) разделяют возможности pytest, pytest-asyncio,
pytest-mock, pytest-cov и xdist. Параллельный запуск требует независимых данных и учитывает,
что session fixture создаётся отдельно в каждом worker, а не один раз на все процессы.

## Частые ошибки

| Ошибка | Исправление |
| --- | --- |
| `minversion` подписан как версия Python | Это минимальная версия pytest; Python ограничивают метаданными проекта |
| `-k 'not slow'` якобы фильтрует marker | `-k` выбирает по именам/keywords; для marker используй `-m` |
| `assert result == result` | Сравни с независимо заданным ожидаемым значением |
| `fixture 'mocker' not found` | Установи pytest-mock именно в тестовое окружение |
| Неизвестный `--json=...` | У pytest нет такого встроенного отчёта; выбери плагин и его документированные флаги |
| Flask использует Django client | Нужна fixture `app.test_client()`; см. [Flask](../../web/flask/testing.md) |
| Обновления библиотек не заметны | Не скрывай все DeprecationWarning по умолчанию; фильтруй конкретную известную причину |
