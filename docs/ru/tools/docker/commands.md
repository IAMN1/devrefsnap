# Выбрать команду Docker Compose

[English](../../../en/tools/docker/commands.md)

Выполняйте команды в каталоге с `compose.yaml`. В примерах ниже сервис `web` взят из [учебного проекта](../../../../examples/tools/docker-basics/compose.yaml). Для первого запуска нужны Docker Engine, плагин Compose и curl. [Запуск из корня репозитория](README.md#первый-запуск).

| Что нужно сделать | Команда для примера | Что вы получите |
| --- | --- | --- |
| Проверить YAML до запуска | `docker compose config -q` | Код 0 для корректной конфигурации. Без `-q` видны итоговые настройки. |
| Собрать образ отдельно | `docker compose build web` | Новый образ или результат из кэша. Работающий контейнер продолжает использовать прежний образ. |
| Запустить приложение в фоне | `docker compose up -d` | Compose создаст недостающие ресурсы и при необходимости пересоздаст изменившиеся контейнеры. |
| Применить изменения файлов из `COPY` | `docker compose up -d --build web` | Compose сначала соберёт образ, затем обновит сервис. [Проверить на файле](#применить-изменение). |
| Узнать состояние и порт | `docker compose ps -a` · `docker compose port web 8000` | Первая команда покажет также остановленные контейнеры. Вторая выведет опубликованный адрес работающего сервиса. |
| Прочитать последние запросы | `docker compose logs --tail 20 -f web` | Последние 20 строк и новые записи. `Ctrl+C` завершит просмотр. |
| Выполнить команду внутри сервиса | `docker compose exec web cat message.txt` | Содержимое файла в работающем контейнере. [Сравнить с run](#выбрать-exec-или-run). |
| Временно остановить и вернуть сервис | `docker compose stop web`, затем `docker compose start web` | Тот же контейнер с прежними настройками. |
| Перезапустить процесс с прежними настройками | `docker compose restart web` | Сервис запустится снова в том же контейнере. |
| Завершить работу с проектом | `docker compose down` | Compose удалит контейнеры и сеть проекта. Именованные тома и образы по умолчанию сохранятся. |

Без флага `-d` команда `up` показывает журналы в терминале. В таком режиме `Ctrl+C` останавливает контейнеры. У команды `logs -f` то же сочетание клавиш оставляет сервис работать в фоне.

По умолчанию Compose берёт имя проекта из имени каталога, если имя не задано другим способом. Из корня репозитория укажите путь к файлу через `-f`, например `docker compose -f examples/tools/docker-basics/compose.yaml config --services`. Для второго экземпляра задайте другое имя через `-p` перед подкомандой. При последующих вызовах указывайте то же имя. Второму экземпляру нужен отдельный свободный порт на компьютере. [Выбор проекта и файла](https://docs.docker.com/reference/cli/docker/compose/).

## Выбрать exec или run

Сначала запустите `web` через `docker compose up -d --build`. Затем сравните команды из каталога примера.

```bash
docker compose exec web cat message.txt
docker compose run --rm web cat message.txt
```

Обе команды выведут `Hello from Docker!` для исходного примера. Первая читает файл прямо в работающем контейнере. Используйте `exec`, чтобы проверить его состояние. В скрипте добавьте `-T`, например `docker compose exec -T web cat message.txt`, чтобы отключить выделение терминала.

Вторая команда создаёт отдельный контейнер по настройкам `web`, выполняет `cat` и удаляет контейнер после выхода. Она подходит для разового теста. Команда `run` по умолчанию пропускает публикацию портов сервиса. В проектах с зависимостями она может запустить нужные сервисы. [Справочник exec](https://docs.docker.com/reference/cli/docker/compose/exec/) · [Справочник run](https://docs.docker.com/reference/cli/docker/compose/run/).

## Применить изменение

В отдельной учебной копии запустите исходный `web`. Замените строку в `message.txt` на `Hello again!`. В базовой конфигурации Dockerfile копирует этот файл в образ, а Compose запускает контейнер без привязки файла с компьютера.

```bash
docker compose restart web
docker compose exec web cat message.txt
docker compose up -d --build web
docker compose exec web cat message.txt
```

После `restart` вы увидите `Hello from Docker!`. После сборки и пересоздания контейнера появится `Hello again!`. Завершите упражнение командой `docker compose down`.

| Что изменилось в вашем проекте | Что выполнить | Почему |
| --- | --- | --- |
| Dockerfile, исходник из `COPY` или зависимости образа | `docker compose up -d --build` | Нужен образ с новыми файлами |
| `ports` или `environment` в YAML | `docker compose up -d` | Compose создаст контейнер с новой конфигурацией |
| Файл, подключённый через bind mount | Проверьте файл в контейнере через `exec` | Изменение доступно через привязку. Если приложение читает файл только при старте, перезапустите процесс. |
| Опубликованный образ с тем же тегом | В [примере с БД](../compose-and-github-actions.md) выполните `docker compose pull postgres`, затем `docker compose up -d` | `pull` загружает образ. `up` применяет его к сервису. Учитывайте совместимость образа с данными тома. |

[Поведение up](https://docs.docker.com/reference/cli/docker/compose/up/) · [Поведение restart](https://docs.docker.com/reference/cli/docker/compose/restart/).

## Найти причину сбоя

| Симптом | Что проверить | Что сделать дальше |
| --- | --- | --- |
| Docker сообщает, что не может подключиться к daemon | `docker version`: есть ли секция `Server`? | Запустите Docker Engine или Desktop. Проверьте выбранное окружение через `docker context show`. |
| Compose не находит конфигурацию или сервис | `docker compose config --services` из каталога примера | Проверьте путь к YAML и имя сервиса. Для этого проекта ожидается `web`. |
| При запуске занят порт `18081` | Сообщение `port is already allocated` или `address already in use` | Запустите `SITE_PORT=18082 docker compose up -d` со свободным портом. Запросите `http://127.0.0.1:18082/message.txt`. |
| Контейнер завершился или HTTP не отвечает | `docker compose ps -a`, затем `docker compose logs --tail 30 web` | Проверьте команду запуска, адрес прослушивания и результат `docker compose port web 8000`. Состояние `running` само по себе не проверяет HTTP. |
| Сервер вернул HTTP 404 | `docker compose exec web ls /site` | Запросите `/message.txt`. Если вы изменили состав образа, пересоберите сервис. |
| Приложение не находит БД из другого контейнера | В проекте с БД выполните `docker compose ps -a` и `docker compose logs --tail 30 postgres` | Используйте имя сервиса и внутренний порт. Проверьте готовность зависимости. [Сеть и готовность](compose-file.md#подключить-базу-данных). |

Для очистки обычно достаточно `down`. Флаг `-v` удаляет в том числе управляемые именованные тома с данными. Последствия для базы и файлов на компьютере разобраны в [выборе хранилища](compose-file.md#выбрать-хранилище).
