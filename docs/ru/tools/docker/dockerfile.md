# Шпаргалка по Dockerfile

[English](../../../en/tools/docker/dockerfile.md)

Dockerfile описывает, что входит в образ и какую программу контейнер запускает по умолчанию. [Полный Dockerfile сайта](lab.md#dockerfile) · [Как он связан с Compose](guide.md).

## Собрать первый образ

| Задача | Инструкция из примера | Результат |
| --- | --- | --- |
| Выбрать среду | `FROM python:3.14-slim` | Python уже установлен в базовом образе. |
| Задать рабочий каталог | `WORKDIR /site` | Docker создаёт каталог при необходимости. Относительные пути назначения начинаются в нём. |
| Включить файлы | `COPY --chown=10001:10001 pages/ ./` | Файлы из `pages/` попадают в `/site`. Владельцем копий становится пользователь с ID 10001. |
| Запустить без прав root | `USER 10001:10001` | Процесс получает указанные ID пользователя и группы. Для изменения файла ему нужны права записи. |
| Указать внутренний порт | `EXPOSE 8000` | Инструкция документирует порт. За доступ с компьютера отвечает `ports` в Compose или `docker run -p`. |
| Задать сигнал остановки | `STOPSIGNAL SIGINT` | Учебный сервер Python обрабатывает этот сигнал и завершает работу. |
| Выбрать команду запуска | `CMD ["python", "-m", "http.server", "8000", "--bind", "0.0.0.0"]` | Контейнер запускает сервер. Элемент массива соответствует одному аргументу. |

Из каталога с Dockerfile команда `docker build -t site:local .` соберёт образ с тегом `site:local`. Команда `docker run --rm site:local python --version` заменит стандартную команду для одного запуска и покажет версию Python. Для поддерживаемой версии Buildx команда `docker build --check .` проверит инструкции. [Справочник Dockerfile](https://docs.docker.com/reference/dockerfile/) · [Проверки сборки](https://docs.docker.com/build/checks/).

Для запуска этого образа без Compose команда `docker run --rm -p 127.0.0.1:18083:8000 site:local` откроет сервер на компьютере. По адресу `http://127.0.0.1:18083/catalog/message.txt` будет доступен файл каталога. Порт должен быть свободен. Нажмите `Ctrl+C` в терминале сервера для остановки.

## Выбрать контекст сборки

В команде `docker build -f dockers/Dockerfile .` параметр `-f` выбирает рецепт, а точка задаёт **контекст** — каталог доступных исходников. Путь слева в `COPY` начинается от корня контекста. Файл `.dockerignore` в корне исключает лишнее. При ошибке `COPY … not found` проверьте контекст, имя файла и правила исключения. [Рабочий .dockerignore](../../../../examples/tools/compose-site/.dockerignore) · [Контекст сборки](https://docs.docker.com/build/concepts/context/).

## Сохранить кэш установки

Фрагмент для Python-проекта с зависимостями. Сначала копируется их список, затем устанавливаются пакеты, после этого копируется код.

```dockerfile
COPY requirements.txt ./
RUN python -m pip install --no-cache-dir -r requirements.txt
COPY app.py test_app.py ./
```

Если изменён только `app.py`, Docker может использовать прежний слой установки. Изменение `requirements.txt` потребует новой установки. Параметр `--no-cache-dir` управляет кэшем pip. [Полный Dockerfile с зависимостями](../../../../examples/tools/compose-and-github-actions/Dockerfile) · [Кэш Docker](https://docs.docker.com/build/cache/optimize/).

## Выбрать инструкцию

| Когда нужно значение или действие | Что использовать |
| --- | --- |
| Выполнить команду при сборке | `RUN`, например для установки пакетов |
| Заменить всю команду при запуске | `CMD ["python", "app.py"]` |
| Закрепить программу и менять только аргументы | `ENTRYPOINT ["python", "-m", "http.server"]` и `CMD ["8000"]`. Аргумент `9000` после имени образа заменит порт. |
| Передать параметр сборки | `ARG PYTHON_VERSION=3.14` перед `FROM python:${PYTHON_VERSION}-slim`. Значение задаёт `docker build --build-arg PYTHON_VERSION=3.14 .`. |
| Задать окружение программы | `ENV PYTHONUNBUFFERED=1`. Значение можно изменить через `environment` сервиса. |

Если нужна одна и та же версия базового образа при повторной сборке, закрепите образ по digest. Теги могут получать обновления.

В JSON-массиве `CMD` и `ENTRYPOINT` оболочка не подставляет `$VAR`. Для секретов сборки у BuildKit есть отдельный механизм. [Секреты сборки](https://docs.docker.com/build/building/secrets/).

## Разделить сборку и запуск

Если компилятор нужен только при сборке, дайте стадии имя через `FROM … AS builder`. В следующей стадии используйте `COPY --from=builder`, чтобы перенести результат. Сервис может выбрать стадию через `build.target`. [Полный пример с uv и условия переноса среды Python](../../python/tooling/uv/automation.md#docker) · [Выбор стадии в Compose](compose-file.md#указать-dockerfile).
