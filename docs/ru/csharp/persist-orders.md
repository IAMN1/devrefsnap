# Сохранить заказ в SQLite и прочитать его после перезапуска .NET-сервиса

[C#](README.md) · [English](../../en/csharp/persist-orders.md) · [Первый HTTP-сервис](first-http-service.md)

Первый сервис рассчитывал стоимость доставки. Теперь клиент отправит заказ на 4999 центов, получит идентификатор и сможет вернуться за результатом. Вы остановите процесс целиком и прочитаете заказ через новый процесс. Данные останутся в одном файле SQLite.

| Задача | Ожидаемый результат |
| --- | --- |
| [Создать заказ](#create-order) | `201 Created`, стоимость доставки 500 центов и адрес заказа в заголовке `Location` |
| [Прочитать заказ после перезапуска](#restart) | `200 OK`, тот же идентификатор, сумма и стоимость доставки |
| [Проверить неизвестный номер](#missing-order) | `404 Not Found` |

## Подготовить учебную базу

Нужны .NET SDK 10.0.x, Bash или Zsh и `curl`. Для первого запуска нужен доступ к NuGet. [Проект сервиса](../../../examples/csharp/shipping/Orders.Api/Orders.Api.csproj) подключает провайдер `Microsoft.EntityFrameworkCore.Sqlite` 10.0.15. SQLite работает внутри процесса. Отдельно запускать сервер БД не требуется.

В первом терминале перейдите в корень репозитория. Выполните этот блок **один раз**. Он создаёт отдельный каталог и показывает путь к учебной базе. Сохраните путь до конца упражнения.

```bash
orders_dir=$(mktemp -d)
orders_project=examples/csharp/shipping/Orders.Api
export ConnectionStrings__Orders="Data Source=$orders_dir/orders.db"
printf '%s\n' "$orders_dir/orders.db"
```

Запустите сервис в том же терминале. Два подчёркивания в имени переменной передают .NET настройку `ConnectionStrings:Orders`. Сервис откроет указанный файл и при первом запуске создаст таблицу `Orders`.

```bash
dotnet run --project "$orders_project" --no-launch-profile -- --urls http://127.0.0.1:5081
```

Дождитесь сообщения `Now listening on: http://127.0.0.1:5081`. Если порт занят, замените `5081` в команде запуска и во всех запросах.

## Создать заказ и получить его адрес

Во втором терминале отправьте JSON. Параметр `-d` указывает `curl` отправить запрос методом `POST`. Параметр `-i` выводит заголовки вместе с телом ответа.

```bash
curl -i -H 'Content-Type: application/json' -d '{"orderTotalInCents":4999}' http://127.0.0.1:5081/orders
```

Для первого заказа в новой базе ответ содержит следующие строки. Остальные заголовки опущены.

```http
HTTP/1.1 201 Created
Location: /orders/1

{"id":1,"orderTotalInCents":4999,"feeInCents":500}
```

`id` присвоила база. Клиент передал только сумму. Сервис вычислил доставку тем же [правилом](../../../examples/csharp/shipping/Shipping/ShippingFee.cs), что и в первом уроке. Запомните путь из `Location`. Каждый успешный повтор `POST` создаёт отдельный заказ со своим идентификатором.

## Остановить процесс и прочитать тот же заказ

В первом терминале нажмите `Ctrl+C`. Дождитесь приглашения оболочки. Повторите только команду запуска. Если повторить весь блок подготовки, сервис откроет другой файл базы.

```bash
dotnet run --project "$orders_project" --no-launch-profile -- --urls http://127.0.0.1:5081
```

После сообщения о запуске вернитесь во второй терминал. Запросите путь из `Location`. В примере это `/orders/1`.

```bash
curl -i http://127.0.0.1:5081/orders/1
```

Ожидайте `200 OK` и прежнее тело `{"id":1,"orderTotalInCents":4999,"feeInCents":500}`. Между запусками вы не отправляли новый заказ. Новый процесс прочитал сохранённую строку из файла.

<a id="missing-order"></a>

## Проверить отсутствие заказа

В новой базе с одним заказом запросите другой номер.

```bash
curl -i http://127.0.0.1:5081/orders/999
```

Сервис вернёт `404 Not Found`. Если такой ответ пришёл для созданного заказа, сверьте номер с `Location` и путь к базе с путём первого запуска.

Проверьте также входные данные. Если отправить отрицательную сумму или пропустить поле `orderTotalInCents`, сервис вернёт `400 Bad Request`. Обработчик завершит запрос до добавления заказа.

После упражнения остановите сервис через `Ctrl+C`. Если учебные данные больше не нужны, удалите созданный временный каталог после остановки. Удаление каталога сотрёт сохранённые в нём заказы.

## Как строка переживает перезапуск

[Модель и контекст](../../../examples/csharp/shipping/Orders.Api/OrdersDb.cs) связывают класс `Order` с таблицей `Orders`. Контекст `OrdersDb` отслеживает изменения объектов в пределах запроса. Провайдер SQLite переводит операции EF Core в SQL. [Обработчик POST](../../../examples/csharp/shipping/Orders.Api/Program.cs) выполняет три действия:

```csharp
db.Orders.Add(order);
await db.SaveChangesAsync(token);
return Results.Created($"/orders/{order.Id}", order);
```

`Add` помечает новый объект для вставки. При `SaveChangesAsync` EF Core записывает строку и получает её ключ. Только после успешной записи обработчик отправляет `201` и включает этот ключ в адрес. Для `GET` приложение получает новый контекст и ищет строку по первичному ключу. Метод `AsNoTracking()` подходит для чтения без последующего изменения объекта.

При старте `EnsureCreatedAsync()` создаёт схему в пустой базе. Этот приём подходит для учебной базы с фиксированной моделью. Для изменения существующей схемы с сохранением данных используйте миграции EF Core.
