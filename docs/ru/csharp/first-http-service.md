# Первый HTTP-сервис на .NET

[C#](README.md) · [English](../../en/csharp/first-http-service.md)

Запустите сервис расчёта доставки на своём компьютере. Передайте сумму заказа в адресе браузера. Для заказа в 4999 центов сервис вернёт `{"feeInCents":500}`. При сумме 5000 центов доставка бесплатна.

### Что такое сервис в этом примере

Консольная программа может вычислить результат один раз и завершиться. Здесь процесс остаётся запущенным и обслуживает новые запросы. Браузер или `curl` выступает клиентом. ASP.NET Core принимает HTTP-запрос и передаёт его обработчику. Клиент получает код состояния и тело ответа.

Слово «сервис» встречается в .NET в нескольких значениях. Здесь это отдельное HTTP-приложение. Фоновая служба может брать задания из очереди. Внедряемой службой называют объект, который приложение передаёт другим объектам. [Фоновые службы .NET](https://learn.microsoft.com/en-us/dotnet/core/extensions/workers) · [Внедрение зависимостей](practice.md#patterns)

## Запустить сервис и получить ответ

Установите [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0). Проверьте версию командой `dotnet --version` в каталоге репозитория. Для примера нужна версия `10.0.x`. SDK включает веб-сервер Kestrel. Для просмотра статуса и JSON из терминала понадобится `curl`.

Из корня репозитория запустите [проект сервиса](../../../examples/csharp/shipping/Shipping.Api/Shipping.Api.csproj).

```bash
dotnet run --project examples/csharp/shipping/Shipping.Api --no-launch-profile -- --urls http://127.0.0.1:5080
```

Дождитесь сообщения `Now listening on: http://127.0.0.1:5080`. Оставьте этот терминал открытым. Адрес `127.0.0.1` доступен на вашем компьютере. Число `5080` обозначает порт. Если порт занят, выберите свободный порт и замените `5080` в команде запуска и адресах запросов.

Откройте `http://127.0.0.1:5080/shipping/quote?orderTotalInCents=4999` в браузере. Чтобы увидеть статус вместе с телом ответа, выполните команду во втором терминале.

```bash
curl -i 'http://127.0.0.1:5080/shipping/quote?orderTotalInCents=4999'
```

Измените только сумму в конце адреса. Сервис продолжит обрабатывать запросы в том же процессе.

| Сумма в центах | Статус HTTP | Тело ответа |
| ---: | --- | --- |
| 4999 | 200 OK | `{"feeInCents":500}` |
| 5000 | 200 OK | `{"feeInCents":0}` |
| −1 (в адресе `-1`) | 400 Bad Request | `{"error":"Order total must be non-negative."}` |

Если браузер возвращает `404` по адресу `/`, откройте путь `/shipping/quote` с параметром суммы. Если соединение отклонено, проверьте адрес и сообщение о запуске в первом терминале. Для остановки нажмите в нём `Ctrl+C`.

## Проследить запрос в коде

Откройте [Program.cs](../../../examples/csharp/shipping/Shipping.Api/Program.cs). В примере одна конечная точка (эндпоинт). Метод HTTP и путь определяют, какой обработчик получит запрос.

```csharp
app.MapGet("/shipping/quote", QuoteShipping);
```

1. При запуске `MapGet` связывает метод `GET` и путь `/shipping/quote` с функцией `QuoteShipping`. Вызов `app.Run()` запускает сервер и ожидает остановки.
2. При запросе ASP.NET Core берёт `orderTotalInCents=4999` из адреса и передаёт обработчику целое число `4999`.
3. Обработчик проверяет сумму. Для отрицательного числа он сразу возвращает `400`. Для допустимой суммы он вызывает [ShippingFee.Calculate](../../../examples/csharp/shipping/Shipping/ShippingFee.cs). Порог бесплатной доставки задан в этой библиотеке.
4. Обработчик возвращает `Results.Ok(new { feeInCents })`. ASP.NET Core записывает статус `200` и сериализует результат в JSON. Запрос только вычисляет цену. Заказ в базе не создаётся.

## Проверить HTTP-контракт

Для первого запуска тестов нужен доступ к NuGet. Из корня репозитория выполните команду.

```bash
dotnet test examples/csharp/shipping/Shipping.Api.Tests/Shipping.Api.Tests.csproj
```

Ожидайте три пройденных тестовых случая. [Тесты HTTP](../../../examples/csharp/shipping/Shipping.Api.Tests/ShippingQuoteTests.cs) запускают приложение через `WebApplicationFactory<Program>`. Клиент отправляет запросы тестовому серверу в памяти. Порт `5080` для этого не нужен. Если обработчик вернёт верное число под другим именем поля или заменит `400` на `200`, тест обнаружит изменение контракта.

[Модульные тесты](tooling-and-testing.md#tests) вызывают функцию расчёта напрямую. Интеграционные тесты дополнительно проходят через маршрутизацию, привязку параметра и запись HTTP-ответа. Запуск с `curl` отдельно проверяет, что Kestrel слушает указанный порт.
